\chapter{Background and related work}
\label{chap:background}

\section{Browser agents and indirect prompt injection}

An LLM agent places a generative model in a feedback loop of goals,
observations, decisions, tool calls, and results. ReAct made the
reasoning--action interleaving explicit, while Toolformer studied how models
can learn to invoke tools~\cite{yao2023react,schick2023toolformer}. Browser
agents extend that loop to URLs, page representations, interactive elements,
and code-capable actions. WebArena and WorkArena evaluate such agents through
executable environments and task-specific evaluators, including state and
answer checks~\cite{zhou2024webarena,drouin2024workarena}. Their structure
highlights two properties relevant here: success is a validated task outcome,
not a plausible response, and observations contain data outside the
operator's control.

Prompt injection exploits the fact that instructions and data share the same
model context. Direct attacks alter the user's prompt; indirect attacks arrive
through retrieved content that the application expected to treat as data.
Greshake et al. demonstrated indirect prompt-injection attacks in synthetic
LLM-integrated applications and through local web content, including data
exfiltration and worm-like propagation~\cite{greshake2023indirect}. A
browser-agent attacker can place equivalent
instructions in a page, user-generated record, link label, or stored result.
The agent encounters them while acting with the user's delegated authority. For
example, injected issue content can divert an agent asked to comment on an
issue towards account settings, with the attacker goal of making the benchmark
user's profile public~\cite{evtimov2025wasp}. The page supplies the instruction,
but the navigation occurs within the benchmark user's authenticated sandbox
session.

This differs from conventional parser injection. A browser agent is
deliberately expected to understand previously unseen prose, so a fixed grammar
cannot by itself establish which source has authority. Delimiters can mark the
distinction between trusted instructions and untrusted input, but page text can
imitate them and the model must still decide which instruction has authority.
Formalisations and benchmarks identify this instruction--data confusion as a
central mechanism~\cite{liu2024formalizing,yi2025bipia}; the next subsection
separates detector, trajectory, and final-state evidence.

The threat also extends beyond the current page: extracted page text and tool
results can cross secondary model calls, while stored history can reintroduce
hostile content later. Multimodal agents add pixels: image-hijack work shows that
specially optimised adversarial images can carry the behavioural effect of a
chosen text prompt and redirect a vision-language model's behaviour
~\cite{bailey2024imagehijacks}. A filter over the Document Object Model (DOM),
the browser's structured representation of a page, cannot remove text rendered
only in pixels. Visual observations therefore form a distinct threat surface
with their own controls; text sanitisation does not automatically cover them.

\subsection{What an agent-security evaluation must measure}

Prompt-injection evaluation spans several distinct units. A detector labels a
piece of text; an action monitor labels a proposed or executed effect; an
end-to-end oracle checks whether the user or attacker changed the environment
as intended. High detector recall can coexist with a compromised trajectory if
the model is only warned or if a dangerous effect bypasses the monitored
channel. Conversely, low terminal attack success can reflect an agent that was
diverted but lacked the capability or remaining steps to finish the attack.

AgentDojo addresses this by pairing realistic user tasks with attacker goals
in executable banking, messaging, travel, and workspace environments
~\cite{debenedetti2024agentdojo}. Its native oracles score both goals through
task-specific checks that may inspect environment state and model output. WASP
applies a similar distinction to browser agents and uses an LLM judge to assess
whether a trajectory has been diverted before the terminal goal is achieved
~\cite{evtimov2025wasp}. The two benchmarks therefore complement one another:
AgentDojo provides controlled evidence about tool-agent effects, whereas WASP
adds browser-native observations, navigation, and re-planning.
Their absolute rates cannot be pooled because their tasks, action spaces, and
oracles differ. ST-WebAgentBench broadens the picture further by studying
policy compliance through Completion Under Policy and Risk Ratio
~\cite{levy2026stwebagentbench}. These measures must be read together because
detection, risky execution, policy compliance, and final-state success reveal
different parts of system behaviour.

This dissertation therefore treats security and utility as a joint outcome.
It reports native user completion, native attacker success, useful-and-secure
completion, attacker-directed attempts and executions, and recorded
enforcement events alongside trajectory outcomes, while separating scripted
controls from actual human intervention. The combination guards against two
misleading conclusions: calling an inactive agent secure, or calling a capable
but compromised agent useful.

\section{Defence design space}

\subsection{Model-facing defences}

Model-facing defences try to help the planner recognise which content deserves
instructional authority. BIPIA evaluates reminders, boundary awareness,
in-context examples, and training across indirect-injection tasks
~\cite{yi2025bipia}. Spotlighting instead uses delimiting, datamarking, or
encoding to keep the distinction between trusted instructions and untrusted
input salient to the model~\cite{hines2024spotlighting}.

Training can make this separation part of model behaviour. StruQ uses
structured instruction tuning to distinguish prompt and data channels
~\cite{chen2025struq}, while SecAlign uses preference optimisation to favour
responses that follow the legitimate instruction over the injection
~\cite{chen2025secalign}. Both report greater resistance to the evaluated
attacks with limited utility loss in their settings. On its principal
AlpacaFarm evaluation, SecAlign reports 0\% attack success for the evaluated
optimisation-free attacks and rates mainly below 10\% for stronger
optimisation-based attacks, with utility similar to its
non-preference-optimised counterparts. A separate out-of-distribution SEP
Ignore evaluation reports 11.0\%, 3.6\%, and 6.5\% attack success when the
injection appears at the start, middle, and end of the input. These findings
remain bound to the paper's models, tasks, and attacks. A later diagnostic
shows why attack rejection and benign utility must be read together: across
its reasoning benchmarks and defended pipelines, benign suffix-task rejection
rose from below 10\% to as high as 90\%. The authors link these failures to position,
trigger-token, and topic correlations, suggesting that trained defences can
rely on narrow surface cues without reliably identifying malicious intent
~\cite{li2026surfaceheuristics}.

Other defences act during inference. Task Shield checks whether each instruction
and proposed tool call contributes to the user's stated goal
~\cite{jia2025taskshield}. Under the one-trial-per-task Important
Instructions attack condition on AgentDojo with GPT-4o, its authors report
2.07\% attack success and 69.79\% utility under attack. MELON instead reruns
the agent trajectory with the user prompt masked and treats similarity between
the original and counterfactual tool calls as evidence of hijacking. The paper
notes that response-based attacks without tool calls can evade this comparison
~\cite{zhu2025melon}. Both ask whether planned behaviour remains dependent on
the authorised task and report AgentDojo trade-offs within their own
configurations; Sentinel also tests transfer through WASP's browser-native
loop. Even within AgentDojo, differences in models, attack construction,
scaffolds, defence mechanisms, and metric definitions make the headline rates
contextual and do not provide a controlled ranking against Sentinel.

Detection supplies an inspectable decision before processed content reaches
the downstream LLM. Detect-and-Remove separates document-level attack
identification from sentence-level removal or generative extraction followed
by longest-common-substring removal~\cite{chen2025detectremove}. Its
effectiveness depends on detecting an attack and identifying the region that
can be removed without destroying the task. Distribution shift remains
fundamental: finite corpora cannot cover all wordings, encodings, page contexts,
and adaptive strategies. White-box optimisation against specific defences has
outperformed non-adaptive attacks in the evaluated settings
~\cite{zhan2025adaptive}. Sentinel therefore uses detection to govern
observations while retaining policy and pre-execution checks as separate layers.

Sentinel therefore combines advisory model-facing guidance with external
observation governance and action policy. This defence-in-depth design
preserves runtime authority.

\subsection{System-level authority}

System-level work moves selected security and execution decisions outside
unconstrained model reasoning, although some designs retain LLM components in
the wider control architecture. CaMeL extracts control and data flow from a
trusted query, confines untrusted data to constrained processing, and enforces
capabilities at tool calls~\cite{debenedetti2025camel}. Fides applies information-flow
control: confidentiality and integrity labels propagate through planning,
deterministic policies govern tool effects, and information can be selectively
hidden from the planner~\cite{costa2025fides}. Progent represents
privilege as symbolic rules over tool names and arguments, checks every tool
call deterministically, applies privilege narrowing automatically, and can
require approval before an expansion. Its main experiments use Auto-Approve,
so they do not measure human-reviewed expansion~\cite{shi2025progent}.
PRUDENTIA builds on Fides by making planning policy-aware and evaluating
autonomy through task completion at intervention budgets and trace-derived
oversight load under assumed approval~\cite{kolluri2026prudentia}.

Other systems choose different trusted abstractions.
AgentSpec provides a lightweight language of triggers, predicates, and runtime
enforcement actions~\cite{wang2026agentspec}. DRIFT derives a minimal function
trajectory and parameter checklist from the trusted query, validates
deviations, and masks conflicting instructions before they persist in memory
~\cite{li2025drift}. IPIGuard plans an initial tool-dependency graph before
exposure to external data and constrains later execution to its traversal,
while allowing read-only query nodes to be added during execution
~\cite{an2025ipiguard}. VIGIL takes a different route: it permits speculative
reasoning over the tool stream, then verifies a proposed effect against the
trusted intent before commitment~\cite{lin2026vigil}. AttriGuard instead tests
whether a proposed tool call survives teacher-forced shadow replay under
control-attenuated external observations~\cite{he2026attriguard}. Reported
attack-success rates across these systems are not directly comparable because
each changes a different part of the agent stack and is evaluated under
different policies, models, and tasks. Any assurance is also conditional on the
system's trusted abstraction and expressible policy.

\section{Protection principles for agent runtimes}

The reference-monitor concept requires a mechanism to be invoked on every
protected operation, isolated from the subject it constrains, and small enough
to analyse~\cite{anderson1972computersecurity}. Complete mediation, fail-safe
defaults, and least privilege provide corresponding design tests
~\cite{saltzer1975protection}. A language model is a poor monitor for its own
effects because hostile input can influence its internal state. A wrapper at
the executor can satisfy the structural requirement that every action in its
governed tool path crosses one decision point, even though natural-language
risk classification remains empirical.

Information-flow control asks where data originated and which sinks it may
reach. Denning's lattice model formalised label-constrained flow
~\cite{denning1976lattice}. Browser-agent values are less structured: page
content becomes model context and a click can disclose information without an
explicit network API. At each action assessment, Sentinel derives a bounded
dynamic model: wrapped browser observations carry untrusted provenance,
detections add injection taint, recognised values add sensitive categories,
and actions expose
capabilities such as navigation, page write, file access, and code execution.
These labels give the policy engine concrete source--sink facts to enforce at
execution time. However, they are operational controls and do not prove that
every information flow is isolated.

Runtime enforcement also needs a precise authority protocol. Effective
human-in-the-loop security depends on communication, processing, application,
and resulting behaviour~\cite{cranor2008humanloop}; automation research
likewise separates information acquisition, information analysis, decision and
action selection, and action implementation
~\cite{parasuraman2000automation}. Sentinel therefore maps hard refusal,
narrow approval, takeover, and observation review to distinct server outcomes.
This structure prevents a generic confirmation from weakening a hard rule.
Whether the interface helps people make sound choices remains a separate
human-subject question, especially because warning design affects attention and
response~\cite{sunshine2009cryingwolf,akhawe2013warningland}.

\section{Research gap}

Prior work spans learned separation, detection, structured control, information
flow, and runtime rules. The gap is whether an independent layer can govern
browser-agent observation and action while retaining useful replanning and
reducing attacker-serving execution. AgentDojo tests the mechanism, WASP
browser-native transfer, and the server-owned workflow selective operator
control.
